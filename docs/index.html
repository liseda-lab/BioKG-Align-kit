BioKG-Align: Link Prediction and Typing over Ontology-Derived Biomedical Knowledge Graphs

BioKG-Align reframes biomedical ontology matching as relation-aware candidate ranking over knowledge graphs. Systems receive a source entity and a fixed set of target candidates, then rank candidate-relation pairs for equivalence or directional subsumption.

Overview

Biomedical alignment for graph, text, and neuro-symbolic methods

Biomedical knowledge is distributed across independently developed ontologies and controlled vocabularies. Aligning these resources supports search, data integration, clinical research, machine learning, and auditable knowledge base construction.

The challenge exposes ontology alignment through a familiar machine learning interface: typed link prediction over fixed candidate sets. Participants may use graph triples, node properties, and optional Datalog rules derived from ontology structure.

Task

Rank candidate-relation pairs across ontology pairs

Input

Each query provides a source entity, a target ontology, and a fixed list of target candidates. The official challenge uses exactly 50 candidates per query, giving 50 × 3 = 150 candidate-relation pairs per query that a system must score.

Output

Submissions score candidate-relation pairs using the official relation names: equivalent, source_subsumed_by_target, and source_subsumes_target.

Correctness

A prediction is relevant only when both the target entity and the relation type match the hidden reference alignment.

Public by design

Participants receive graph files, public train and validation labels, public candidate sets, baseline code, documentation, manifests, and a local validation scorer.

Private by design

Hidden test answers, full hidden references, split construction details, licensed raw sources, and official hidden scorer assets are not part of this public kit.

Evaluation

Relation-aware ranking with typed predictions

The primary leaderboard metric is macro-averaged Preferred Relation-Aware MRR across the three ontology-pair tasks. A ranked item is relevant only if the target entity and the relation type both match the preferred gold typed pair for the query. The secondary metric is macro-averaged Hierarchy-Aware Typed nDCG@10, which awards graded partial credit to hierarchically adjacent candidates.

Additional strict metrics (Preferred Typed Hits@1/5/10) and diagnostic metrics (entity-only MRR, relation accuracy on the preferred entity, relation macro-F1) are reported alongside the headline metrics. Confidence intervals and significance testing are TBD.

Local scores ≠ leaderboard scores. The kit's local scorer reports both diagnostic metrics (diagnostic_*; untyped MRR, binary-relevance nDCG@10, top-1 macro-F1) and the headline metric families (preferred_typed_* and hierarchy_aware_typed_*) when the required answer-adjacent files *.preferred.tsv and *.graded.tsv are present. Diagnostic metrics are useful for quick iteration but do not match the leaderboard. The public data release will ship pre-computed *.preferred.tsv and *.graded.tsv files for train and valid splits alongside the candidate files; an offline graded-relevance archive is also planned for Zenodo distribution. Until that release lands, the kit's build-graded-relevance CLI helper rebuilds the graded-relevance file deterministically from preferred pairs, candidates, and the target-ontology hierarchy.

Baselines

Starting points for several participant communities

Random

Seeded PRNG scores per candidate-relation pair. Calibration anchor for diagnostic metrics; shipped in the kit.

Hybrid lexical

Token-overlap and character-ngram similarity on labels and synonyms, with a small equivalence-relation bias. Shipped in the kit.

Graph embedding (KGE)

TransE, DistMult, RotatE, and ComplEx trained on the released graph triples. Predictions bundled in the public release.

Text-enhanced

Word-embedding-based scoring over labels and synonyms. Predictions bundled in the public release.

Rule-aware

TBD Planned baseline demonstrating use of Datalog-derived features.

Rules

Draft contest rules

  • Participants must submit predictions in the official format.
  • Predictions must score only candidate entities provided in the evaluation files.
  • Released triples, node properties, Datalog rules, training anchors, and validation labels may be used.
  • External resources and pretrained models may be used if they are public, cited, and declared.
  • Hidden test labels, unpublished reference alignments, and manual annotation of the hidden test set are not allowed.
  • Final leaderboard submissions may require code and sufficient reproduction instructions.
  • Submitted systems are research prototypes and must not claim clinical validity.

Final rules, external-resource policy, team limits, submission limits, and reproduction requirements are TBD.

FAQ

Pre-launch questions

Is the final real dataset available?

Not yet. This repository contains a small runnable example and participant tools. Final ontology versions, counts, and download links are TBD.

Will participants need OWL expertise?

No. The challenge interface is graph-learning-ready: triples, node properties, Datalog rules, and candidate TSV files. Ontology-specific background will be documented for participants who want it.

Can external biomedical resources be used?

The draft plan allows public, cited, and declared external resources. The final policy is TBD and will be published before launch.

How is hidden ground truth protected?

Hidden test labels are not included in public candidate files, graph triples, released alignments, or Datalog rules. The official scorer will keep hidden answers server-side.
